# Accuracy report

Generated by `npm run check`. Simplified files: tolerance 30 m (Douglas-Peucker, topology-preserving), coordinates rounded to 5 decimals.

## Method

- 20,000 points per chamber, drawn uniformly from California's bounding box (lon -124.48 to -114.13, lat 32.53 to 42.01) with a seeded PRNG (mulberry32, seeds 20211220 Assembly / 20211221 Senate); only points that fall inside some district of the unsimplified CRC file are kept (45950 and 45857 draws needed).
- Each point is looked up in the simplified file and in the reference. A mismatch is a different district number (or no district in the simplified file).
- Distances are metres from the point to the nearest boundary segment of the simplified file (local equirectangular approximation). For a mismatch that distance is how far the point sits from the boundary it was misassigned across.

## Recommended boundary margin

**35 m.** If the located point is within 35 m of any district boundary, the app should ask the user to confirm the district instead of trusting the lookup.

Basis: simplification tolerance 30 m + 1 m coordinate rounding + 2 m NAD83/WGS84 datum slack = 33 m; worst observed mismatch against the unsimplified CRC data 14.1 m; the larger value is rounded up to the next 5 m. This covers the file only. It does not include the error of the device location or of a geocoder, which the app must add to the margin.
