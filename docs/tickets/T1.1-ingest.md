## Task
Build the TypeScript job that turns the California Legislative Counsel "pubinfo" bulk zip into the JSON snapshot defined in `schema/snapshot-v1.ts`, with fixture-based tests and fail-closed checks.

## Read first
- `schema/snapshot-v1.ts` — the frozen output contract. Do not change it. If it cannot express something, return `DECISION NEEDED: <question>` instead of guessing.
- `docs/reference/capublic.sql` — the official table definitions (column order of every `.dat` file).
- `docs/reference/probe.py` and `docs/reference/measure_text.py` — working Python that reads the same file (the `.dat` parser, docx text extraction, Digest extraction). Port the logic; they are ours, MIT.
- The real file: `.cache/pubinfo_2025.zip` (1.2 GB, git-ignored; if missing, wait for it or download `https://downloads.leginfo.legislature.ca.gov/pubinfo_2025.zip` with curl and a browser User-Agent).

## Hard rules
- **Never write a bill, vote, legislator, committee or date from memory.** Everything in fixtures, tables and tests is copied from the real file. Each fixture records the source file name, its Last-Modified (`2026-11-16T05:26:36Z` for `pubinfo_2025.zip`) and the original 1-based row numbers.
- Do not copy code from `openstates/openstates-scrapers` (GPL) or `david-welker/pubinfo-tools` (no licence). Do not open them.
- Dependencies: MIT/BSD/Apache/ISC only. Suggested: `yauzl` (random-access zip), `fflate` (docx unzip), `zod` (validators), `vitest`, `tsx`, `typescript`. Install locally with npm. No global installs.
- No secrets, no network calls other than the documented download. Node 24, ESM, strict TypeScript.

## Source format facts (measured)
- `.dat` files are UTF-8, tab-separated, one row per line; strings are wrapped in backticks, `NULL` is null, LOB columns hold a file name such as `BILL_VERSION_TBL_973.lob` that is another entry in the same zip.
- `BILL_VERSION_TBL` LOB = bill XML; the Digest is `<caml:DigestText>…</caml:DigestText>`. `BILL_ANALYSIS_TBL` LOB = a `.docx` (zip); text is `word/document.xml` with `</w:p>` as paragraph break.
- Vote codes are only `AYE`, `NOE`, `ABS`. Vote rows name the member by `legislator_name`, which equals `LEGISLATOR_TBL.author_name` (e.g. `Petrie-Norris`, `Blanca Rubio`).
- The zip has 205,287 entries. Never extract it to disk; read entries on demand. A reader abstraction must accept either a zip or a directory (fixtures are a directory).

## Scope rules (decided; implement exactly)
1. **Measures:** only `AB`, `SB`, `ACA`, `SCA`. Everything else is dropped from the output but still counted in `Manifest.counts`.
2. **People:** `tables/people-<session>.json` maps every `(house, vote name)` and every named `LEGISLATOR_TBL` row to exactly one `PersonId` (`ca-<a|s>-<ascii-slug-of-author_name>`). Provide `npm run draft-people` that drafts it from `LEGISLATOR_TBL`; then fix by hand the cases the draft cannot know, using only what the file shows: AD15 has two rows (`Ávila Farías` / `Avila Farias`) that are one person; Senate vote name `Weber` is the SD39 member `Weber Pierson`. Two different people who held the same district (AD63: Essayli, Johnson) stay two people. The build **fails** on an unmapped vote name, an unmapped named legislator row, or a name mapped to two people. Party: map `DEM`→`Democratic`, `REP`→`Republican`, anything else verbatim.
3. **Floor vote classification:** `tables/floor-vote-classification.json` lists every floor `file_location` value (Senate values normalised by stripping a trailing ` (Supplemental File N)`), each with `kind` = `third_reading` | `consent` | `concurrence` | `null` (excluded) and the description copied from `LOCATION_CODE_TBL` where one exists. Starting point:
   - Assembly `AF0240`, `AF0250` → third_reading; `AF0280`, `AF0290`, `AF0295`, `AF0297` → consent; `AF0180`, `AF0185`, `AF0300`, `AF0310` → concurrence; `AF0150`, `AF0160` and other codes → excluded.
   - Senate `Senate 3rd Reading`, `Assembly 3rd Reading` → third_reading; `Special Consent`, `Consent Calendar 2nd` → consent; `Unfinished Business` → concurrence only when the motion text contains `Concurrence`; `Senate 2nd Reading`, `Assembly 2nd Reading` → excluded.
   - `W/O REF. TO FILE` and null: classify by motion text (`Third Reading` / `3rd Reading` → third_reading, `Concurrence` → concurrence, otherwise excluded).
   - Regardless of location, exclude a roll call whose motion text matches reconsideration, amendment (`Amend` as a word), withdraw, re-refer, or lay on the table.
   - **Urgency:** some Assembly motions read `… Third Reading Urgency`. If the same bill has a non-urgency third-reading roll call in that house on the same date, exclude the urgency one; if the urgency roll call is the only one, count it as third_reading. Report how many fall in each case.
   - The build **fails** on any floor `file_location` not in the table.
4. **`final` flag:** per bill and house, the last `third_reading`/`consent` roll call and the last `concurrence` roll call, ordered by date, then time, then numeric `vote_date_seq`.
5. **Version voted on:** among that bill's versions whose action is `Introduced` or starts with `Amended` (never `Enrolled`/`Chaptered`), the newest with date strictly before the vote date. If such a version has the same date as the vote, still pick the one before it and set `versionInferred: true`. If no version is strictly earlier (vote on the introduction date), use the Introduced version with `versionInferred: true`.
6. **`noRollCall`:** for each in-scope bill and house where the bill history has an action matching `Read third time. Passed.` or `…concurred in.` with `(Ayes N. Noes M.` in that house, but no `final` roll call of the matching kind exists, emit a `PassageWithoutRollCall`. (Known cases: SB 1058 and SB 1438 in the Assembly, 2026-06-25.) Decide the house of a history action from `primary_location`/the running "In Senate"/"In Assembly" state; if you cannot do it reliably, return `DECISION NEEDED`.
7. **Stage:** `finished` when `current_status` is `Chaptered` (outcome chaptered), `Vetoed` (vetoed), `Died` (died), `Failed` or `Failed Passage in Committee` (failed); also `finished` with outcome `session_ended` for every other bill when the session has ended. Otherwise: `floor` (rank 1) when `current_status` is `In Floor Process`; `passed_house` (2) when status is `Passed`/`Enrolled` or the bill's `current_house` differs from its house of origin; `cleared_committee` (3) when it has at least one passing committee roll call in its current house; `hearing_scheduled` (4) when a `COMMITTEE_HEARING_TBL` date is on or after the source date; else `introduced` (5). A session has ended when the source date is after Nov 30 of the session's second year.
8. **Issues:** `tables/issues.json` is the fixed list (`id`, `n`, `name`), and `tables/committees-<session>.json` maps every committee `location_code` (`CS..`, `CX..`) to an `issueId` or null. Draft both from the committee names in `LOCATION_CODE_TBL`: one neutral issue per policy subject, named with the committee's own words (e.g. Education, Health, Housing, Public Safety, Judiciary, Transportation, Natural Resources and Water, Environmental Quality, Labor and Employment, Elections, Local Government, Revenue and Taxation, Insurance, Banking and Finance, Agriculture, Energy and Utilities, Privacy and Consumer Protection, Human Services, Higher Education, Military and Veterans Affairs, Governmental Organization, Emergency Management, Business and Professions, Arts and Entertainment, Aging, Communications …). Assembly and Senate committees on the same subject share an issue. Appropriations, Rules, Budget, and Budget and Fiscal Review map to null. No adjectives, no advocacy wording. Every committee code present in the file must be in the table or the build fails. `Bill.committees` comes from `COMMITTEE_HEARING_TBL.location_code` and committee roll calls, in order of first appearance.
9. **Analysis:** per bill, the latest analysis (max `analysis_date`, then `analysis_id`). `text` is the whole document verbatim. The section parser is conservative: fill `digest`, `support`, `opposition`, `positionsVerified`, `argumentsInSupport`, `argumentsInOpposition` only when the heading is found unambiguously, and every value must be an exact slice of `text` (test this property over the fixtures). When unsure, null. "None received"/"None on file" lists become an empty array.
10. **Digest:** from the latest version's XML. Keep paragraph breaks.
11. **Shards:** `analysisShardKey` from the schema file.
12. **Output files:** `core-<hash8>.json`, `votes-<hash8>.json`, `digests-<hash8>.json`, `analysis-<shard>-<hash8>.json`, `latest.json`, plus `manifests/<snapshotId>.json`. Deterministic: same input, byte-identical output (stable key order, sorted arrays; `generatedAt` passed in by flag for tests).

## Fail-closed checks (exit non-zero, write nothing to the output directory)
- Any output file fails its zod validator (`schema/validate-v1.ts`, which you write to mirror the types exactly; also emit JSON Schema files to `schema/json/` if zod supports it).
- Any record lacks `src`.
- Fewer than 99.9% of roll calls in the source have member rows matching the official ayes and noes.
- Any counted floor roll call has fewer than 75 Assembly or 37 Senate members.
- With `--manifests <dir>`: any `counts` value for a session is below 98% of the highest value in any earlier manifest for that session.
- Rules 2, 3 and 8 failures above.

## CLI
- `npm run ingest -- --source <zip|dir> --session 20252026 --source-file <name> --source-date <ISO> [--etag <s>] [--min-app-version 0.1.0] [--manifests <dir>] [--previous <id,id,…>] --out <dir>`
- `npm run make-fixture -- --source <zip> --bills <comma list> --out fixtures/<name>` writes a directory in pubinfo layout holding only the rows for those bills (whole `LEGISLATOR_TBL`, `LOCATION_CODE_TBL`; only referenced motions and LOBs; analyses limited to the latest plus one committee analysis per bill) and a `FIXTURE.md` listing source file, date and original row numbers per table.
- `npm test`, `npm run typecheck`.
