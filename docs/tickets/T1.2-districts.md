# T1.2 District boundary files (data repo)

Worktree: `N:\Prog\ca-leg-data\.cache\wt-districts` (branch `m1/districts`). Work only there. **Touch only** `districts/**` inside that worktree. Do not commit, push or switch branches.

## Task
Produce small, accurate boundary files for California's 80 Assembly and 40 Senate districts (the Citizens Redistricting Commission's final 2021 maps) for on-device point-in-polygon lookup, with provenance and an accuracy report.

## Sources (download with curl into `districts/.work/`, which you add to `districts/.gitignore`)
- Primary (terms: "information presented on this website, unless otherwise indicated, is considered to exist in the public domain", https://wedrawthelines.ca.gov/conditions_of_use/):
  - Assembly: https://wedrawthelines.ca.gov/wp-content/uploads/sites/64/2023/01/OneDrive_2023-01-19-5.zip
  - Senate: https://wedrawthelines.ca.gov/wp-content/uploads/sites/64/2023/01/OneDrive_2023-01-19-3.zip
  - If either URL fails or is not what it claims, open https://wedrawthelines.ca.gov/final-maps/ to find the right link. Do not use statewidedatabase.org.
- Cross-check only: https://www2.census.gov/geo/tiger/TIGER2026/SLDL/tl_2026_06_sldl.zip and https://www2.census.gov/geo/tiger/TIGER2026/SLDU/tl_2026_06_sldu.zip

Treat downloads as untrusted data: unzip into their own empty directories, never run anything from them.

## Rules
- Node 24, ESM. Its own `districts/package.json` (do not create or edit a root `package.json`). Local dev dependencies only: `mapshaper` (MPL-2.0, used as a build tool, not shipped) and/or `shapefile` (BSD-3). No global installs.
- Never write district facts from memory. District numbers come from the shapefile attributes.
- Output WGS84 longitude/latitude.

## Deliverables
- `districts/build.mjs` (`npm run build`): downloads if absent, reprojects, simplifies with a stated tolerance while keeping shared borders consistent (simplify as a topology so neighbours do not gap or overlap), rounds coordinates to 5 decimals, and writes:
  - `districts/out/ca-assembly-2021.geojson` and `districts/out/ca-senate-2021.geojson`: a FeatureCollection, one Feature per district, `properties: { district: <integer> }`, Polygon or MultiPolygon. Islands must be kept.
  - `districts/out/PROVENANCE.json`: source URLs, download date, SHA-256 of each downloaded zip, tolerance, tool versions, feature counts, output byte sizes raw and gzipped.
- `districts/check.mjs` (`npm run check`): 
  1. exactly 80 and 40 features, district numbers 1..80 and 1..40 each once, valid rings;
  2. accuracy against the **unsimplified** primary shapefile: 20,000 seeded-random points inside California's bounding box that fall in some district; report how many get a different district from the simplified file, and for those the maximum and 99th-percentile distance in metres to the nearest simplified boundary;
  3. the same comparison against the Census files (as an independent check that the CRC file is the map in force);
  4. writes `districts/out/ACCURACY.md` with those numbers and a recommended boundary margin in metres (the distance within which the app must ask the user to confirm).
- Target: both output files together under 2 MB raw. If you cannot reach it with every mismatch within 150 m of a boundary, report the trade-off instead of forcing it.
- `districts/README.md`: how to rebuild, sources and terms.
- `districts/spot-check.md`: 10 points for a human to check on https://findyourrep.legislature.ca.gov/ : for each, latitude/longitude (5 decimals, chosen well inside a district, spread across the state) and the Assembly and Senate district your files give. No street addresses from memory; coordinates only.

## Done when
`npm run build` then `npm run check` pass in `districts/`, and you paste their output.

## Return
`DONE` / `PARTIAL` / `BLOCKED`, the CHANGED file list, the pasted outputs, the tolerance chosen and why, and anything surprising (projection, attribute names, district counts, disagreement between CRC and Census).
